

# Task 004: タイトル補足表示と銘柄検索画面

## 目的

ホーム画面のタイトル直下に「もし株」が何のためのアプリか一目で分かる短い説明を追加する。

あわせて、ROADMAPのPhase 3に沿って、日本株を探して「もし株」の記録を始めるための銘柄検索画面を実装する。

今回は検索画面のUIと画面遷移までを対象とし、yfinanceによる実際の株価取得は次のTaskで行う。

UIの基準は引き続き以下のモックとする。

`docs/mockups/moshi_kabu_ui_mock_v1.png`

## 実装範囲

### 1. ホーム画面のタイトル直下に説明文を追加

ホーム画面上部のタイトル：

`もし株`

の直下に、以下の説明文を小さく表示する。

`買わなかった株の答え合わせアプリ`

表示方針：

- タイトルより十分小さい文字サイズにする
- 薄いグレー〜ブラウン系など、主張しすぎない文字色にする
- 中央揃えを基本とする
- タイトルとの間隔は狭めにし、1つのブランド表示として見えるようにする
- 猫や吹き出しより目立たせない
- ホーム画面全体の縦方向のバランスを崩さない

### 2. 「もし株を記録する」ボタンから銘柄検索画面へ遷移

- ホーム画面の「もし株を記録する」ボタンをタップすると銘柄検索画面へ遷移する
- Flutter標準の画面遷移でよい
- 戻る操作でホーム画面へ戻れるようにする
- 不要に複雑なルーティングライブラリは導入しない

### 3. 銘柄検索画面の基本UI

画面タイトル：

`迷った株を記録`

主な要素：

- 戻るボタン
- 検索入力欄
- 検索結果一覧

検索入力欄のプレースホルダー例：

`銘柄名・銘柄コードで検索`

デザインはモック2画面目を参考にする。

### 4. 銘柄検索

今回は実APIを使用せず、ローカルのダミー銘柄データを使って検索UIを成立させる。

最低限、以下のような日本株のダミーデータを用意する。

- 8306 / 三菱UFJフィナンシャル・グループ
- 285A / キオクシアホールディングス
- 4661 / オリエンタルランド
- 9432 / NTT
- 6758 / ソニーグループ

検索条件：

- 銘柄コードの部分一致
- 銘柄名の部分一致
- 入力が空の場合は、候補を表示するか、シンプルな案内表示にする

今回は日本株のみを対象とする。

### 5. 検索結果一覧

各検索結果には最低限以下を表示する。

- 銘柄コード
- 銘柄名

必要であれば右端に矢印など、選択可能であることが分かる控えめなUIを追加してよい。

今回は株価を実表示しない。

yfinance連携後に価格情報を追加しやすい構造にしておく。

### 6. 銘柄選択時の扱い

- 検索結果の銘柄をタップできるようにする
- 今回は次の「見送り記録画面」そのものはまだ実装しない
- タップ時は、選択した銘柄を保持できる最小限の構造まで用意してよい
- 未実装画面へ無理に遷移させない
- 必要であれば、選択したことが確認できる簡単な仮表示に留める

## UI方針

- Task 002・003で整えたホーム画面のデザインを維持する
- クリーム系背景
- 緑をメインカラー
- 角丸カード・角丸検索欄
- 情報を詰め込みすぎない
- 既存の証券会社アプリのような高密度UIにしない
- 「検索して選ぶ」ことだけに集中できる画面にする
- `docs/mockups/moshi_kabu_ui_mock_v1.png` の2画面目を主な参考にする
