
# Task 003: ホーム画面の状態表示

## 目的

Task 002で整えたホーム画面に、将来の実データ連携を想定した「状態ごとの見せ方」を追加する。

今回はまだ端末内保存や株価取得は実装せず、ダミーデータだけを使って以下の状態を確認できるようにする。

- 答え合わせ対象がない状態
- 答え合わせ対象がある状態
- 最近のもし株がない状態
- 最近のもし株がある状態

UIの基準は引き続き以下のモックとする。

`docs/mockups/moshi_kabu_ui_mock_v1.png`

## 実装範囲

### 1. 答え合わせ待ちエリアの状態表示

答え合わせ対象が0件の場合：

- 現在の空状態カードを表示する
- 猫の吹き出しは通常状態の文言にする

例：

`今日は気になる株あった？`

答え合わせ対象が1件以上ある場合：

- ホーム画面上部で答え合わせ可能な件数がすぐ分かるようにする
- 猫の吹き出しを答え合わせ案内に切り替える

例：

`3件、答え合わせできるよ！`

- 「答え合わせ待ち」カード内にも件数を表示する
- 答え合わせ対象があることが、ホーム画面を開いた直後に視認できるようにする
- 今回はタップ後の画面遷移は実装しない

### 2. 最近のもし株エリアの状態表示

最近のもし株が0件の場合：

- 現在の空状態カードを表示する

最近のもし株がある場合：

- ダミーデータを使って、最近記録したもし株を最大3件程度表示する
- 各行には最低限以下を表示する
  - 銘柄名
  - 記録時価格
  - 記録日時
- 実際の騰落率や答え合わせ結果はまだ表示しない
- 情報を詰め込みすぎず、モックのホーム画面の密度を参考にする

ダミーデータ例：

- 三菱UFJフィナンシャル・グループ / 2,135円 / 8/11 09:42
- キオクシアHD / 8,000円 / 8/10 14:21
- オリエンタルランド / 4,580円 / 8/9 10:15

### 3. 猫の吹き出し切り替え

ホーム画面の状態に応じて、猫の吹き出し文言を切り替えられる構造にする。

最低限、以下の2パターンを用意する。

通常状態：

`今日は気になる株あった？`

答え合わせあり：

`3件、答え合わせできるよ！`

今回はダミーの状態値をコード上で切り替えて確認できればよい。

### 4. 状態表示用の構造整理

- UIコード内に状態判定を過度に直書きしない
- 将来、端末内保存データへ差し替えやすい構造にする
- ただしRiverpod、Bloc等の大きな状態管理ライブラリは今回導入しない
- Task 003に必要な最小限の構造に留める

## UI方針

- Task 002で完成したデザインを崩さない
- `docs/mockups/moshi_kabu_ui_mock_v1.png` を引き続き参照する
- 猫キャラクターはモック内の猫を基準にする
- 答え合わせ対象がある場合も、警告画面のように強くしすぎない
- 可愛く、やわらかく、でも情報は一目で分かるようにする
- ホーム画面のシンプルさを維持する
