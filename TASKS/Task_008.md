

# Task 008: 端末内保存・記録完了・Yahoo!ファイナンス外部リンク

## 目的

Task 007までに作成した見送り記録ドラフトを、実際に端末内へ保存できるようにする。

あわせて、記録完了後の完了画面、ホーム画面の「最近のもし株」への反映、銘柄詳細からYahoo!ファイナンスを開く外部リンクを実装する。

今回のTaskで、以下の基本フローを初めて一通り成立させる。

**銘柄検索 → 株価取得 → 見送り理由選択 → 答え合わせ期間設定 → 記録 → 完了画面 → ホームへ反映**

通知、答え合わせ日の取引日補正、答え合わせ日の終値取得、学習分析はまだ実装しない。

UIの基準は引き続き以下のモックとする。

`docs/mockups/moshi_kabu_ui_mock_v1.png`

---

## 実装範囲

### 1. 端末内への見送り記録保存

Task 007までに `SkipRecordDraft` に保持している内容を、端末内へ永続保存する。

MVPではクラウド保存・ログイン・アカウント同期は行わない。

保存方法はFlutterで一般的なローカル永続化手段を利用し、将来の拡張に耐えられる構造にする。

SQLite系、Isar、Hive等のいずれかを採用してよいが、今回必要な範囲を超えて複雑な構成にしないこと。

保存対象は最低限以下とする。

- 一意なrecord id
- 銘柄コード
- 銘柄名
- 見送り時の価格
- 記録日時
- 見送り理由の内部ID / enum
- 見送り理由の表示文言
- `その他` 選択時の自由記述
- 答え合わせ期間の種類
- カスタムの場合の指定日
- 答え合わせ予定日の元情報
- 答え合わせ済み / 未実施を管理できる状態
- 答え合わせ価格（現時点ではnull）

今回は答え合わせ日の土日祝補正を行わないため、保存時点では「選択した期間・指定日」を正しく保持することを優先する。

### 2. 保存用モデル

`SkipRecordDraft` は画面入力中の一時データとして維持し、永続保存用のモデルと役割を分ける。

例：

- `SkipRecordDraft`
  - 画面入力中
- `SkipRecord`
  - 保存済みデータ

UIとローカルDB処理を直接密結合させない。

将来、保存方式を変更しても画面側の変更を最小限にできるようRepository等の薄い抽象化を入れてよい。

### 3. 「この内容で記録する」ボタンを実保存へ接続

Task 006・007で用意した以下のボタン：

`この内容で記録する`

を実際の保存処理へ接続する。

ボタンタップ時の流れ：

1. 現在の入力内容を確認
2. 記録日時を自動タイムスタンプとして確定
3. 見送り記録を端末内へ保存
4. 保存成功後に記録完了画面へ遷移

保存中は二重タップ・二重登録を防止する。

保存失敗時：

- アプリをクラッシュさせない
- ユーザー向けエラーを表示する
- 入力中の内容を失わない

エラー表示例：

`記録を保存できませんでした。もう一度お試しください。`

### 4. 記録日時

記録日時はユーザー入力項目にしない。

`この内容で記録する` を実行した時点の日時を自動で保存する。

Task 006で削除した独立した「記録日時」入力カードは復活させない。

### 5. 記録完了画面

保存成功後、モック3画面目を参考に記録完了画面へ遷移する。

主な表示内容：

- 記録完了を示す可愛い演出
- 猫キャラクター
- `記録しました！`
- 短い補足メッセージ
- 銘柄名
- 見送り価格
- 記録日時
- 見送り理由
- 答え合わせ設定
- `ホームに戻る` ボタン

補足メッセージ例：

`未来の自分と答え合わせを楽しみに待ちましょう`

猫キャラクターは、既存モック・既存キャラクターの雰囲気を維持する。

新しい別デザインの猫を作らない。

### 6. 完了画面からホームへ戻る

`ホームに戻る` をタップするとホーム画面へ戻る。

その際、保存した記録がホームの「最近のもし株」に即時反映されるようにする。

不要な画面がNavigation stackに大量に残らないようにする。

ユーザーがホームへ戻った後、戻る操作で再び記録完了画面へ戻ってしまうような不自然な遷移は避ける。

### 7. ホーム画面「最近のもし株」を実データへ変更

Task 003で使用していたダミーデータを、保存済みの実データへ置き換える。

表示ルール：

- 新しい記録から最大3件程度
- 銘柄名
- 見送り価格
- 記録日時

まだ答え合わせを実施していないため、騰落率は表示しない。

記録が0件の場合は既存の空状態を表示する。

Task 003のダミーデータはMVPの通常表示から削除する。

### 8. ホーム画面の件数状態も実データ準備へ寄せる

まだ答え合わせロジックは実装しないため、ベルの答え合わせ待ち件数を本判定へは接続しない。

ただし将来、保存済み `SkipRecord` から答え合わせ対象件数を算出できる構造へ差し替えやすくしておく。

Task 005で作ったダミーの答え合わせ3件表示を通常利用時に固定表示し続けないこと。

答え合わせ判定が未実装の間は、0件扱いまたは明確な開発用状態として分離する。

### 9. Yahoo!ファイナンスへの外部リンク

見送り記録画面の銘柄情報カード内に、詳細情報を外部で確認できる補助リンクを追加する。

表示例：

`Yahoo!ファイナンスで見る ↗`

配置方針：

- 銘柄情報カードの右上または情報の邪魔にならない位置
- 小さめの補助リンクとして表示
- 主アクションである見送り記録より目立たせない
- 既存の可愛いUIを壊さない

タップ時：

- 対象銘柄のYahoo!ファイナンス銘柄ページをSafari等の外部ブラウザで開く
- Flutterの `url_launcher` 等を使用してよい
- アプリ内WebViewは今回使わない

URL生成は銘柄コードから一元的に行い、UI内へURL文字列を直書きしない。

将来リンク先を変更しやすい構造にする。

URLが開けない場合はクラッシュせず、ユーザー向けに簡単なエラー表示を出す。

### 10. Yahoo!ファイナンスリンクの位置づけ

「もし株」内では以下の情報を抱え込みすぎない。

- 詳細チャート
- ニュース
- 決算
- 掲示板
- 詳細なファンダメンタル情報

詳細確認は外部サービスへ委ね、「もし株」は見送り記録と答え合わせ体験に集中する。

### 11. 会社ロゴ

- ダミーロゴを追加しない
- 手動で主要銘柄だけ画像を持たない
- 将来、自動取得できる仕組みを別Taskで検討する
