

# Task 006: 見送り記録画面

## 目的

Task 005までに実装した銘柄検索・実株価取得を使い、選択した株について「なぜ買わなかったのか」を簡単に記録できる画面を実装する。

今回は、見送り理由の選択と記録内容の確認UIまでを対象とする。

端末内への本保存、答え合わせ日設定の本実装、通知、答え合わせ処理はまだ実装しない。

UIの基準は以下のモックとする。

`docs/mockups/moshi_kabu_ui_mock_v1.png`

---

## 実装範囲

### 1. 銘柄選択後に見送り記録画面を表示

Task 004・005の銘柄検索画面で銘柄を選択した後、見送り記録画面へ遷移する。

画面上部には、選択した銘柄の情報を表示する。

最低限表示する情報：

- 銘柄コード
- 銘柄名
- 現在値または直近取得価格
- 価格取得時刻

株価取得中はローディング表示、取得失敗時はTask 005のエラー表示方針を維持する。

### 2. 画面タイトル

画面タイトルは以下を基本とする。

`迷った株を記録`

左上には戻る「＜」ボタンを表示し、前の銘柄検索画面へ戻れるようにする。

### 3. 「なぜ見送った？」セクション

銘柄情報カードの下に、以下の見出しを表示する。

`なぜ見送った？`

見送り理由は、ユーザーが短時間で選べるように「アイコン＋短い言葉」のカード形式にする。

2列×2行の4択を基本とする。

#### 選択肢1

アイコン例：上昇チャート、価格タグなど

表示文言：

`高いと思った`

意味：

- 割高に感じた
- 上がりすぎだと感じた
- 高値掴みが怖かった

#### 選択肢2

アイコン例：下降チャート

表示文言：

`まだ下がりそう`

意味：

- まだ下落が続きそう
- もう少し押し目を待ちたい
- 底が見えない

#### 選択肢3

アイコン例：新聞、カレンダー、雲など

表示文言：

`材料・地合いが不安`

意味：

- 決算や重要イベント前
- ニュースや材料が不安
- 市場全体の地合いが悪い
- 外部環境が不透明

#### 選択肢4

アイコン例：財布、貯金箱

表示文言：

`自分側の事情`

意味：

- 資金を温存したい
- 余力が少ない
- 他の銘柄を優先したい
- 今回は投資余力を使いたくない

4つの分類は、以下の観点で大きく重複しないようにする。

- 価格水準
- 値動き予想
- 外部環境
- 自分側の事情

### 4. その他

4つの理由カードの下に、横長の「その他」カードを配置する。

表示文言：

`その他`

「その他」を選択した場合のみ、自由記述欄を表示する。

自由記述欄は任意入力とする。

プレースホルダー例：

`見送った理由を入力`

### 5. 選択状態

- 理由は1つだけ選択可能とする
- 選択中のカードは、緑や淡いアクセントカラーで選択状態が明確に分かるようにする
- 未選択のカードは白〜クリーム系背景を維持する
- タップ時に過度なアニメーションは不要
- アイコンと文言の両方をタップ対象にする

### 6. 記録日時

画面内で、見送り記録の日時を表示する。

今回は画面を開いた時点の現在日時を使ってよい。

表示例：

`2026/08/11 10:25`

将来のTaskで実際の保存タイムスタンプとして利用しやすい構造にする。

### 7. 答え合わせ期間の仮表示

今回は答え合わせ期間の本設定はTask 007で実装する。

Task 006では、画面下部に以下を仮表示する。

`答え合わせ：1か月後`

必要であれば右側に小さく `変更` と表示してよいが、今回タップ処理は不要。

### 8. 「この内容で記録する」ボタン

画面下部に大きなアクションボタンを配置する。

表示文言：

`この内容で記録する`

UIはモック2画面目を参考にし、丸みのある大きなボタンにする。

ボタンの有効条件：

- 見送り理由が1つ選択されている

理由未選択時：

- ボタンを無効状態にする

理由選択後：

- ボタンを有効状態にする

今回はまだ端末内保存は行わない。

ボタンタップ時は、将来の保存処理へつなげやすいcallback構造まで用意してよい。

### 9. 記録完了画面について

Task 006では、モック3画面目の「記録しました！」画面はまだ本実装しない。

記録完了画面は、端末保存を実装するTask以降で追加する。

## UI方針

- `docs/mockups/moshi_kabu_ui_mock_v1.png` の2画面目を最優先で参照する
- クリーム系背景
- 角丸カード
- 緑をメインカラー
- 見送り理由カードは2列×2行
- 各理由はアイコン＋短い言葉で一目で理解できるようにする
- 情報を詰め込みすぎない
- 10秒以内で記録準備できる操作感を意識する
- 既存の証券アプリのような高密度UIにしない
- 猫キャラクターは今回の画面には必須ではない
