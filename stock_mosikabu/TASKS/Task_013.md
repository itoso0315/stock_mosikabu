
# Task 013: 見送り傾向分析画面・ホームの一言インサイト

## 目的

Task 012までで、答え合わせ済みの見送り記録を `振り返り` タブから一覧で見返せるようにする。

Task 013では、その蓄積データを使って「自分がどんな理由で見送りやすいか」「その見送り判断のあと株価がどう動いたか」を分析し、ユーザー自身の判断傾向に気づけるようにする。

ホーム画面では分析結果を詰め込みすぎず、**短い一言インサイトを1つだけ**表示する。

詳細は別の「見送り傾向」画面で確認できる構成にする。

今回のゴールは、

**ホームで気づきを1つ見る → 詳しく見る → 自分の見送り傾向を確認する**

という導線を完成させること。

---

## 画面の役割

### ホーム

ホームは分析結果を大量に表示する場所ではない。

`あなたの見送り傾向` カードでは、現在の保存データから最も分かりやすい気づきを1つだけ表示する。

例：

`最近は「高いと思った」で見送ることが多いみたい`

または

`「まだ下がりそう」で見送った株は平均 -3.4%`

その下に

`詳しく見る >`

を表示し、タップで詳細分析画面へ遷移する。

### 見送り傾向詳細画面

答え合わせ済みの見送り記録を集計し、ユーザー自身の判断のクセを複数の視点から確認する場所とする。

「正解率」「勝率」のように判断を採点する画面にはしない。

---

## 分析対象データ

原則として、`SkipRecord` のうち答え合わせ結果が正常に保存されている `completed` 記録のみを分析対象とする。

最低限利用する項目：

- 見送り理由
- 見送り価格
- 答え合わせ価格
- 騰落率
- 答え合わせ期間
- 記録日時
- 答え合わせ実行日時

未答え合わせ・取得失敗・結果未保存の記録は分析対象に含めない。

---

## 実装範囲

### 1. ホーム「あなたの見送り傾向」を実データ化

現在ホームにある `あなたの見送り傾向` カードを、保存済みの答え合わせ結果から生成した一言インサイトへ変更する。

ダミー分析値は表示しない。

分析対象データがまだ不足している場合は、既存の空状態を利用する。

例：

`見送りデータがたまると、あなたの判断傾向を振り返れます`

### 2. ホームに表示するインサイトは1つだけ

1回の表示で複数の分析結果を並べない。

ホームでは、ユーザーに最も理解しやすい1つの気づきを表示する。

第一優先の候補：

1. 一番多い見送り理由
2. 理由別の平均騰落率で特徴が強いもの
3. 見送った株の上昇 / 下落比率で特徴が強いもの

実装初期は、最も安定して算出できる `一番多い見送り理由` を優先してよい。

例：

`最近は「高いと思った」で見送ることが多いみたい`

### 3. ホームカードに「詳しく見る」導線

`あなたの見送り傾向` カード内に

`詳しく見る >`

を追加する。

タップ時に新しい `見送り傾向` 画面へ遷移する。

カード全体をタップ可能にしてもよいが、ユーザーが遷移可能だと自然に理解できるUIにする。

### 4. 見送り傾向詳細画面を追加

新しい画面として、以下を追加する。

画面タイトル：

`見送り傾向`

明確な戻るボタン `<` を表示する。

ホームから遷移した場合、戻る操作でホームへ自然に戻る。

### 5. 分析① 一番多い見送り理由

completed記録の見送り理由を集計し、最も多い理由を表示する。

表示内容例：

```text
いちばん多い見送り理由

高いと思った
12件 / 32件
```

必要であれば割合も表示してよい。

例：

`38%`

同数の場合は、無理に1つだけ断定せず、同率であることが分かる表示にしてよい。

### 6. 分析② 理由別の件数

5つの見送り理由ごとに件数を表示する。

対象理由：

- 高いと思った
- まだ下がりそう
- 材料・地合いが不安
- 資金を温存したい
- その他

表示例：

```text
高いと思った          12件
まだ下がりそう         8件
材料・地合いが不安     6件
資金を温存したい       4件
その他                 2件
```

理由カードの既存カラーやアイコンを再利用してよい。

### 7. 分析③ 理由別の平均騰落率

各見送り理由ごとに、答え合わせ時の平均騰落率を算出する。

例：

```text
高いと思った          +5.8%
まだ下がりそう        -2.4%
材料・地合いが不安    +1.1%
資金を温存したい      +3.2%
```

計算対象が0件の理由は `データなし` とする。

色分け：

- プラス：ピンク〜赤系
- マイナス：水色〜青系
- 0%付近：グレー系

Task 011・012と同じ色ルールを再利用する。

### 8. 分析④ 見送った株の上昇 / 下落比率

completed記録全体について、答え合わせ時の結果を以下に分類する。

- 上昇
- 下落
- ほぼ横ばい

MVPでは `0%` を境界にしてよい。

必要であれば将来 `±0.5%` 以内を横ばいとするなど調整できる構造にする。

表示例：

```text
見送った株のその後

上昇  62%
下落  34%
横ばい 4%
```

初期実装では、円グラフなど複雑なグラフは必須としない。

横棒・比率表示・小さなカードなど、可愛いUIで分かりやすく表示する。

### 9. 分析⑤ 平均騰落率

completed記録全体の平均騰落率を表示する。

例：

`見送った株は平均 +3.8%`

この値だけでユーザーの判断を良い / 悪いと評価しない。

### 10. 分析⑥ 最近の傾向

completed記録が一定数ある場合、直近の記録に限定した簡単な傾向を表示してよい。

初期候補：直近5件。

例：

`最近5件は「高いと思った」での見送りが3件`

または

`最近は「資金を温存したい」が増えています`

ただし、データ量が少ない場合は表示しない。

複雑なAI分析や自然言語生成は今回行わない。

### 11. 答え合わせ期間別の違い

保存データから安全に算出できる場合、以下の期間ごとの平均騰落率または件数を表示してよい。

- 3日後
- 1週間後
- 1か月後
- 3か月後
- カスタム

ただしTask 013の必須要件ではない。

UIが過密になる場合は後続Taskへ回してよい。

### 12. データ量が少ない場合

completed記録が少ない状態で、断定的な分析を表示しない。

目安として：

- 0件：分析不可の空状態
- 1〜2件：件数や結果は表示できるが「傾向」と断定しすぎない
- 3件以上：簡単な傾向表示を開始してよい

表示例：

`もう少し答え合わせがたまると、傾向が見えてきます`

### 13. データ更新

Task 011で新しい答え合わせがcompletedになったあと、ホームまたは見送り傾向画面を開くと最新分析へ反映されること。

アプリ再起動を必要としない。

### 14. 分析ロジックの分離

集計処理を `home_screen.dart` や分析画面へ直接大量に書かない。

例：

- `SkipRecordAnalysisService`
- `SkipRecordInsightsService`

等のサービスへ分析ロジックを分離してよい。

UIは分析結果を受け取って表示する役割に寄せる。

将来分析項目を追加しやすい構造にする。

---

## ホーム一言インサイトの選定ルール

初期実装では、複雑な優先順位エンジンは不要。

以下の順で安全に表示してよい。

1. completed記録が3件未満
   - `もう少し答え合わせがたまると、傾向が見えてきます`

2. completed記録が3件以上
   - 最頻出の見送り理由を表示

表示例：

`最近は「高いと思った」で見送ることが多いみたい`

将来、より特徴的な分析を優先表示するロジックへ差し替え可能な構造にする。

## UI方針

- ホームでは分析を1つだけ見せる
- 詳細画面では複数の分析カードを縦に並べる
- クリーム系背景
- 緑を基本カラー
- 大きめの角丸カード
- 柔らかいゴシック系
- 明朝体っぽい細い文字を使わない
- 理由ごとの既存カラフルアイコンを活用してよい
- プラス / マイナスの色ルールをTask 011・012と統一
- 少し可愛いが幼すぎない
- 数字を詰め込みすぎない
- 「自分を採点されている」印象を与えない

---

## 文言方針

ユーザーの判断を責めたり断定評価したりしない。

使用してよい：

- `〜で見送ることが多いみたい`
- `〜という傾向があります`
- `見送った株は平均 +3.8%でした`
- `最近は〜が増えています`

使用しない：

- `判断が間違っています`
- `見送り失敗率`
- `正解率`
- `投資判断が下手`
- `買うべきでした`

---

## 今回やらないこと

- AIによる投資アドバイス
- 「次は買うべき」などの売買推奨
- 勝率 / 正解率
- 投資判断の点数化
- 高度な統計分析
- 複雑なグラフ
- 月別推移グラフ
- 銘柄別分析
- 検索 / 絞り込み
- シェア機能
- OS通知
- Push通知
- 正式な休場日補正
- 会社ロゴ自動取得
- ログイン
- クラウド同期

---

## 実装上の注意

- Task 012までのホーム・振り返り・答え合わせ機能を壊さない
- completed記録だけを分析対象にする
- 保存済み結果を利用し、分析のために株価APIへ再アクセスしない
- 見送り理由の内部enum / IDを維持する
- 分析ロジックをUIから分離する
- データが少ない状態で断定しすぎない
- 0件・少数データでもクラッシュしない
- Task 013の範囲外を先回り実装しない
