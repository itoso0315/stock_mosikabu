

# Task 010: 日本株銘柄検索・サジェスト対応

## 目的

現在の銘柄検索はTask 004で用意した少数のダミー銘柄のみを対象としているため、実際に使いたい銘柄を検索できない。

Task 010では、日本株の銘柄マスタを使って検索候補をリアルタイム表示できるようにし、

**文字入力 → 候補表示 → 銘柄選択 → 株価取得 → 見送り記録**

の流れを実用レベルへ近づける。

今回は銘柄検索・サジェスト機能の改善に限定し、保存、答え合わせ、通知、学習分析は変更しない。

---

## 実装範囲

### 1. 日本株銘柄マスタを用意する

検索対象として、日本株の銘柄コードと会社名を保持する銘柄マスタを用意する。

最低限保持する情報：

- 銘柄コード
- 会社名

例：

- 8306 三菱UFJフィナンシャル・グループ
- 285A キオクシアホールディングス
- 4661 オリエンタルランド
- 9432 NTT
- 6758 ソニーグループ

銘柄マスタはUIへ直書きせず、検索サービスまたはRepository等から参照できる構造にする。

今回は公開アプリ前の開発段階なので、合法的に利用可能な公開情報・静的データ・開発用マスタを利用してよい。

ただし、特定サイトのHTMLをスクレイピングして銘柄一覧を都度取得する実装は行わない。

### 2. 入力中にリアルタイムで候補表示

検索ボックスへ文字を入力すると、検索結果候補をリアルタイムで表示する。

検索ボタン押下を必須にしない。

例：

`フジ`

と入力した場合、条件に一致する銘柄候補を複数表示できるようにする。

検索結果は入力のたびに更新する。

### 3. 会社名の部分一致検索

会社名の完全一致だけでなく部分一致で検索できるようにする。

例：

- `三菱` → 三菱UFJフィナンシャル・グループ等
- `フジ` → フジクラ等
- `ソニー` → ソニーグループ

大文字・小文字の違いがある場合は可能な範囲で吸収する。

### 4. 銘柄コード検索

銘柄コードでも検索できるようにする。

例：

- `8306`
- `9432`
- `285A`

コードの途中まで入力した場合も候補表示できるようにする。

例：

`83`

→ 8306等の候補

### 5. 日本語表記ゆれへの配慮

MVPでは過度に複雑なかな変換エンジンは実装しない。

ただし検索処理は将来、以下へ拡張しやすい構造にする。

- ひらがな / カタカナ
- 全角 / 半角
- 英字の大文字 / 小文字
- スペース有無

今回できる範囲で、最低限の文字正規化を入れてよい。

### 6. 検索候補の表示件数

候補が多すぎる場合は上位10件程度に絞る。

表示例：

```text
5803  フジクラ
4676  フジ・メディア・ホールディングス
6702  富士通
6504  富士電機
```

会社名が長い場合でもレイアウトが崩れないようにする。

### 7. 検索結果カード

各候補には最低限以下を表示する。

- 銘柄コード
- 会社名

デザインは既存の検索画面と統一する。

- クリーム系背景
- 大きめの角丸
- 柔らかいゴシック系
- 選択しやすいタップ領域

会社ロゴは今回実装しない。

### 8. 候補選択後の既存フローを維持

候補をタップした後は、Task 005以降で実装済みの既存フローへ接続する。

具体的には：

1. 選択した銘柄コード・会社名を取得
2. 既存の株価取得処理を実行
3. 見送り記録画面へ遷移
4. Yahoo!ファイナンスリンクも選択銘柄に対応

既存の `StockPriceService` 等を壊さない。

### 9. 空入力時

検索ボックスが空の場合、全銘柄を大量表示しない。

空状態として、検索を促すメッセージを表示してよい。

例：

`会社名または銘柄コードを入力してください`

将来的に最近検索した銘柄を表示する可能性はあるが、今回は実装しない。

### 10. 0件時

一致する銘柄がない場合は、空白のままにせず0件表示を出す。

例：

`該当する銘柄が見つかりませんでした`

ユーザーが検索失敗とアプリ不具合を区別できる表示にする。

### 11. 検索パフォーマンス

文字入力のたびに検索しても、通常利用で体感的な遅延が出ないようにする。

銘柄マスタを毎回ネットワーク取得しない。

ローカルマスタ検索の場合、不要に複雑な非同期処理を増やさない。

必要であればdebounceを入れてよいが、ローカル検索で不要なら導入しなくてよい。

## データ構造

銘柄マスタ用に、既存モデルを流用または新しい軽量モデルを用意する。

例：

```dart
class StockMasterItem {
  final String code;
  final String name;
}
```

検索ロジックと画面表示を分離し、UIへ検索条件を大量に直書きしない。

将来、銘柄マスタの取得元をAPIへ変更しても画面側への影響を小さくする。

---

## UI方針

- 検索入力中に結果がすぐ変わる
- 検索ボタンを押さなくてもよい
- 結果が多すぎて圧迫しない
- タップ対象を十分大きくする
- 会社名・コードの優先順位が分かりやすい
- 既存の可愛い・柔らかいUIを維持する
- 明朝体っぽい細い文字を使わない
- iPhoneの小さい画面でもオーバーフローしない

## 実装上の注意

- Task 009までの既存機能を壊さない
- 現在の5銘柄ダミー検索を実用銘柄マスタ検索へ置き換える
- 銘柄マスタをUIへ直書きしない
- ネットワークに依存しない候補検索を優先する

- Task 010の範囲外を先回り実装しない
