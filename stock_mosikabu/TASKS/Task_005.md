# Task 005: 実株価取得とホーム画面の将来UI骨格

## 目的

銘柄検索画面で選択した日本株について、開発用データソースとして yfinance を使い、実際の株価を取得して表示できる状態にする。

あわせて、今後追加する学習機能・設定機能を見据え、ホーム画面下部に最低限の将来UI骨格を追加する。

今回の主目的は実株価取得であり、見送り記録の保存や通知などはまだ実装しない。

UIの基準は引き続き以下のモックとする。

`docs/mockups/moshi_kabu_ui_mock_v1.png`

---

## 実装範囲

### 1. yfinanceによる株価取得

- 開発初期の株価取得には yfinance を使用する
- 日本株は銘柄コードに `.T` を付与して取得する
- 例：
  - 8306 → `8306.T`
  - 9432 → `9432.T`
- 選択した銘柄の現在値または直近取得可能な価格を取得する
- 株価取得に失敗した場合は、アプリがクラッシュせずエラー表示できるようにする
- 将来、別の株価APIへ差し替えやすいよう、株価取得処理はUIから分離する

### 2. Python / yfinance実行方法

Flutterアプリから yfinance を直接実行するのではなく、株価取得部分はバックエンド層として分離する。

開発段階では最小構成でよい。

方針：

- Pythonで yfinance を利用する
- Flutter側はHTTP等の明確なインターフェース経由で株価取得結果を受け取れる構成にする
- FastAPIを使う場合は、Task 005に必要な最小限のエンドポイントだけ実装する
- 将来データ提供元を変更してもFlutter側の変更を最小限にできる構成にする

最低限必要なレスポンス項目：

- 銘柄コード
- 銘柄名
- 取得価格
- 価格取得時刻

### 3. 銘柄選択後の株価表示

Task 004の検索結果から銘柄を選択した際に、選択銘柄の株価を取得して表示する。

今回は本格的な見送り記録画面はまだ作らず、最低限以下を確認できるUIとする。

- 銘柄コード
- 銘柄名
- 現在値または直近取得価格
- 価格取得時刻
- ローディング状態
- 取得失敗時のエラー状態

UIはモック2画面目の銘柄情報カードを参考にする。

### 4. 会社ロゴについて

今回は会社ロゴ画像を実装しない。

- 手動のダミーロゴ画像は追加しない
- 主要銘柄だけローカル画像を持つ対応もしない
- 将来、銘柄コード等から会社ロゴを自動取得する仕組みを検討する
- 今回は既存のシンプルなプレースホルダー表示を維持してよい

### 5. 「あなたの見送り傾向」カードをホームへ追加

ホーム画面の「最近のもし株」より下に追加する。

見出し：

`あなたの見送り傾向`

MVPではまだ実データ分析を行わない。

表示例：

`見送りデータがたまると、あなたの判断傾向を振り返れます`

UI方針：

- モックのカードを参考
- 小さなグラフ風アイコンを表示してよい
- `+4.8%` などのダミー分析結果は表示しない
- タップ処理はまだ不要
- 大きくしすぎない

### 6. ボトムナビゲーションを追加

ホーム画面下部に以下3タブを追加する。

- ホーム
- 学習
- 設定

初期状態：

- ホームを選択状態として緑で表示
- 学習・設定は未選択状態

今回は学習画面・設定画面そのものは実装しない。

- 学習・設定をタップしても無理に空画面へ遷移させない
- 将来画面追加しやすい構成にする

### 7. 既存ホームUIを維持

以下は維持する。

- `もし株`
- `買わなかった株の答え合わせアプリ`
- 猫キャラクター
- 猫の吹き出し
- 通知ベル
- 「もし株を記録する」ボタン
- 答え合わせ待ち
- 最近のもし株

今回不要な理由でデザイン変更しない。
