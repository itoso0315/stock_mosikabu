# Task 011: 答え合わせ価格取得・騰落率計算・答え合わせ結果画面

## 目的

Task 009までで「答え合わせ日が来た記録」を答え合わせ待ち一覧へ表示できるようになった。

しかし現状は、答え合わせ予定日が到来したことを示すだけで、実際の結果である

**見送り価格 → 答え合わせ価格 → もし買っていたら何％だったか**

が表示されていない。

Task 011では、もし株のコア体験となる「答え合わせ」を成立させる。

実装対象は以下。

- 答え合わせ日の株価取得
- 騰落率計算
- 答え合わせ結果画面
- 答え合わせ済み状態の保存
- 答え合わせ待ち一覧から結果画面への遷移

通知送信、正式な休場日補正、振り返りタブ本実装、学習分析はまだ実装しない。

---

## 基本体験

ユーザーが見送り記録を残し、答え合わせ日が来たあと、

```text
見送り価格 3,515円
        ↓
答え合わせ価格 3,780円
        ↓
もし買っていたら +7.5%
```

のように、結果を直感的に確認できるようにする。

このアプリではユーザーの判断を「正解」「不正解」と評価しない。

表示するのはあくまで、

`もし買っていたら +○○% / -○○%`

という結果のみとする。

## 実装範囲

### 1. 答え合わせ待ちカードをタップ可能にする

Task 009で実装した「答え合わせ待ち一覧」の各記録カードをタップ可能にする。

タップ時：

- 未答え合わせなら答え合わせ処理へ進む
- すでに答え合わせ済みなら保存済み結果を表示する

同じ記録に対して毎回不要な再取得を行わない。

### 2. 答え合わせ対象価格の取得

既存のBackend / 株価取得構造を利用して、答え合わせ対象日の価格を取得する。

対象は日本株。

取得する価格は原則として：

`答え合わせ日の終値`

とする。

今回のTask 011では正式な日本市場カレンダーによる休場日補正はまだ実装しない。

ただし、指定日に価格データが存在しない場合にクラッシュしないようにする。

将来Taskで「次の取引日へ繰り越す」処理へ差し替えやすい構造にする。

### 3. Backend API

現在の最新株価取得APIとは別に、指定日の終値を取得できるAPIを追加してよい。

例：

`GET /api/stocks/{code}/close?date=2026-09-11`

レスポンス例：

```json
{
  "code": "8306",
  "date": "2026-09-11",
  "close": 3780.0,
  "priceDate": "2026-09-11"
}
```

UIからyfinanceを直接呼ばず、既存のBackend経由構造を維持する。

株価Providerは将来差し替え可能な構造を維持する。

### 4. 価格データが存在しない場合

指定日に終値が存在しない場合、ユーザーへ明確な状態を表示する。

例：

`この日の株価を取得できませんでした`

ただし、この時点で記録を「答え合わせ済み」にしない。

再試行できる状態を維持する。

### 5. 騰落率計算

見送り価格と答え合わせ価格から騰落率を計算する。

計算式：

```text
(答え合わせ価格 - 見送り価格)
÷ 見送り価格
× 100
```

例：

```text
見送り価格     3,515円
答え合わせ価格 3,780円

(3,780 - 3,515) / 3,515 × 100
= +7.54%
```

画面表示では原則小数1桁まででよい。

表示例：

`+7.5%`

`-8.7%`

必要に応じて内部値はより高い精度で保持する。

### 6. 値上がり・値下がりの色分け

結果を直感的に理解できるように色分けする。

- プラス：ピンク〜赤系
- マイナス：水色〜青系
- 0%付近：グレー系

日本株アプリとして、一般的な赤＝上昇、青＝下落の見た目に寄せてよい。

既存のクリーム・緑を基調としたUIを壊さないよう、結果部分のみアクセントカラーを使用する。

### 7. 答え合わせ結果画面

新しい「答え合わせ結果画面」を追加する。

画面タイトル例：

`答え合わせ`

主な表示内容：

- 銘柄コード
- 銘柄名
- 見送り価格
- 答え合わせ価格
- 見送り価格から答え合わせ価格への矢印表現
- 騰落率
- 見送り理由
- 記録日時
- 答え合わせ期間
- 実際に価格取得した日

メインメッセージ例：

`もし買っていたら +7.5%`

または

`もし買っていたら -8.7%`

「正解」「不正解」という文言は使わない。

### 8. 結果画面のUI

UIは、既存モックで想定している答え合わせ画面の方向性を参考にする。

結果カードのイメージ：

```text
三菱UFJフィナンシャル・グループ

見送り時      答え合わせ
 3,515円  →    3,780円

       +7.5%
  もし買っていたら
```

騰落率は画面内で最も目立つ情報のひとつとする。

ただし数字を過度に巨大にしない。

### 9. 猫キャラクター

結果画面に既存の猫キャラクターを使ってよい。

結果に応じて猫がユーザーを評価・批判する表現はしない。

例：

- `こんな値動きになったよ`
- `あのときの判断を振り返ってみよう`

のような中立的なトーンにする。

`買えばよかったね`

`見送って正解！`

など、結果論で判断を断定する表現は使用しない。

### 10. 答え合わせ結果の保存

答え合わせ成功時、保存済み `SkipRecord` に結果情報を保持する。

最低限追加・更新する情報：

- 答え合わせ済みフラグ / status
- 答え合わせ価格
- 実際に価格取得した日
- 騰落率
- 答え合わせ実行日時

一度正常に答え合わせできた記録は、アプリ再起動後も結果が残るようにする。

### 11. 答え合わせ済み記録の扱い・通知件数の消化

答え合わせ待ちの記録をユーザーが開き、答え合わせ結果を正常に確認した時点で、その記録は「通知済み / 確認済み」として扱う。

確認済みになった記録は、通常の「答え合わせ待ち」件数から除外する。

例：

答え合わせ待ちが1件
↓
ユーザーがその記録を開いて答え合わせ結果を確認
↓
ベルのバッジは0件になり非表示

複数件ある場合は、確認した記録ぶんだけ件数を減らす。

例：

答え合わせ待ちが3件
↓
1件を確認
↓
ベルのバッジは2件

猫の吹き出しも最新件数へ更新する。

0件になった場合：

`今日は気になる株あった？`

等の通常状態へ戻す。

単にベルを開いただけでは全件を既読扱いにしない。

「答え合わせ結果まで確認した記録」を通知消化済みとして扱う。

### 11-1. 確認済み記録は「振り返り」へ移す

答え合わせ結果を確認済みの記録は、今後ホーム下部ナビの `振り返り` タブで参照する対象データとする。

状態の考え方：

- 答え合わせ前：通常の見送り記録
- 答え合わせ日到来後・未確認：答え合わせ待ち / ベル件数対象
- 答え合わせ結果確認済み：振り返り対象

Task 011では、最低限この状態遷移をデータとして保存する。

`振り返り` タブの完全な一覧UI・フィルタ・分析機能は別Taskで実装してよい。

ただし、Task 011の結果確認後にその記録が再び答え合わせ待ちへ戻らないこと。

### 12. 答え合わせ済み記録の再表示

今回は振り返りタブの完成版UIまでは実装しなくてもよい。

ただし、答え合わせ結果を確認済みの記録は `振り返り` 対象として識別できる状態で保存する。

## 開発用テスト機能との連携

既に実装済みのdebug build限定「開発者メニュー」を利用して、このTaskを待ち時間なしで確認できるようにする。

開発者メニューで

`最新の記録を答え合わせ可能にする`

を実行した記録は、答え合わせ待ち一覧へ表示される。

そのカードをタップし、Task 011の答え合わせ処理へ進めること。

デバッグ用予定日オーバーライドは、本番データの元の答え合わせ期間を破壊しない既存仕様を維持する。

### 開発上の重要事項

開発用オーバーライドで「今日」を答え合わせ可能日にした場合、当日の終値がまだ確定していない時間帯では終値取得ができない可能性がある。

テスト時に実際の終値取得まで確認できるよう、debug build限定で必要なら

- 直近の価格データが存在する取引日をテスト対象日として指定する

または

- 開発者メニューから任意の過去日を答え合わせ対象日に指定できる

など、Task 011の検証に必要な最小限の補助を追加してよい。

ただし本番仕様は変更しないこと。

## データモデル方針

`SkipRecord` の保存済みモデルへ、答え合わせ結果用フィールドを追加する。

例：

```dart
enum AnswerStatus {
  waiting,
  ready,
  completed,
}
```

ただし既存実装との整合性を優先し、不要に大きなモデル変更は行わない。

古い保存データを読み込んだ際、答え合わせ結果用フィールドが存在しなくてもクラッシュしないよう後方互換を持たせる。

## エラー状態

以下のエラーを安全に扱う。

- Backendに接続できない
- 株価取得失敗
- 指定日の価格が存在しない
- 保存更新失敗

エラー時：

- アプリをクラッシュさせない
- 答え合わせ済みにしない
- 再試行できる
- 既存記録を壊さない

表示例：

`答え合わせ価格を取得できませんでした。もう一度お試しください。`
